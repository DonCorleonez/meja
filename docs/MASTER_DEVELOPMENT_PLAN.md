## Review & acceptance policy
Each milestone one PR (split into logically dependent PRs if necessary), never force push. Planning docs written direct to main by ChatGPT; all implementation in branches. Muse starts by reading master + current repo plan/status, then fetches exact refs and existing changes. Update docs/EXECUTION_STATUS.md when starting, when blocked or ready for review, include PR URL; keep current state on main via docs-only update if allowed, otherwise status in PR with direct link. Preserve history append-only. PR contains docs/reviews/<milestone>.md, base/head SHA, scope, files, rule references/visual references, command output and CI links, QA screenshot artifacts, measurements, open risks and explicit checks. Muse does not advance, merge, tag, or deploy until reviewer PASS and owner acceptance. If CHANGES_REQUESTED, fix in same PR and provide new SHA/evidence. If BLOCKED, report missing inputs or decision; don't fabricate.
Reviewer's checklist: (1) verify actual diff and commit SHA (2) map every acceptance item to proof (3) verify rules/source and missing data (4) inspect code/privacy/replay/invariants (5) inspect actual tests and screenshot evidence; run independent tests if environment allows; explicitly say skipped otherwise (6) classify P0/P1/P2/P3 (7) post findings to PR and status: PASS, CHANGES_REQUESTED, or BLOCKED. PASS is technical recommendation not owner authorization. No approval based only on Muse's summary. Owner can accept/reject priorities. Avoid publication of private game code, sensitive details or private rule/component data in this public repo; use private game PRs for those.
Quality gates per game as detailed in plans: lint/typecheck/unit/build, ≥1000 seeded games with genuine termination/invariants/replay, per-rule fixtures, browser mobile/tablet/desktop & offline/save/resume, AI isolated hidden info & measured latency, 80KB initial JS gzip, 150KB transfer, Lighthouse 95, accessibility. No P0/P1 open at RC; P2/P3 explicit owner-approved deferrals. Rulebook fidelity claims cover only verified edition/components, no placeholders mislabeled. No production readiness claims from untested artifacts.
